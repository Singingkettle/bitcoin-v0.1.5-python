# 第 11 章　内存池与手续费

> **本章目标**：弄明白一笔交易从"发出去"到"进区块"之间待在哪里、节点凭什么决定收不收它、
> 手续费规则是什么，以及这套规则后来是怎么演化的。
>
> **对应源码**：[bitcoin/mempool.py](../bitcoin/mempool.py)、`tx.py` 的 `get_min_fee`、`miner.py` 的 `create_new_block`
> 　　**实验**：[labs/lab10_wallet.py](../labs/lab10_wallet.py)（第 4~8 步）

## 11.1　交易的候车室

区块大约每 10 分钟才出一个。一笔交易被广播出来之后、被打包进区块之前的这段时间，它待在哪里？

每个节点的内存里都有一个**内存池**（memory pool，简称 mempool）：
存放"我已经验证过、合法、但还没有被任何区块收录"的交易。它有三个用途：

1. **矿工的原料库**：矿工组装候选区块时，从这里挑交易；
2. **转发的依据**：节点只转发自己内存池里接受了的交易——无效交易在第一个收到它的诚实节点那里就被拦下了，不会扩散；
3. **零确认的依据**：钱包显示的"0/未确认"收款，就来自内存池。

内存池**只存在于内存里**，节点一重启就清空了；而且**每个节点的内存池都可能不一样**
（取决于各自收到了哪些交易、先收到哪笔）。内存池不是共识的一部分——全网达成共识的只有区块链。

## 11.2　两张表

```python
class MemPool:
    def __init__(self, chain):
        self.lock = chain.lock
        self.map_transactions: dict[int, CTransaction] = {}     # 交易哈希 -> 交易
        self.map_next_tx: dict[tuple[int, int], int] = {}       # (前序交易哈希, 输出序号) -> 花费它的池内交易
```

`map_transactions` 好理解。`map_next_tx` 是一张**反向索引**：对池里每笔交易的每个输入，
记下"这个输出被池里的哪笔交易花了"。有了它，检查"新来的交易和池里已有的交易是否双花"只需要查一次表。

（名字沿用原版的 `mapTransactions` 和 `mapNextTx`。）

## 11.3　准入检查

`accept()` 对应原版的 `AcceptTransaction`。一笔交易想进内存池，要过这些关：

```python
    def accept(self, tx, check_inputs=True) -> bool:
        if tx.is_coinbase():                    # ① coinbase 只能出现在区块里，不能单独传播
        if not tx.check_transaction():          # ② 基本格式检查（第 6 章）
        if h in self.map_transactions:          # ③ 池里已经有了
        if self.chain.contains_tx(h):           # ④ 已经在区块里了
        for i, txin in enumerate(tx.vin):       # ⑤ 和池里的交易冲突吗（花了同一笔钱）？
            if key in self.map_next_tx: ...
        if not self._check_inputs(tx):          # ⑥ 输入都存在、没被花过、coinbase 已成熟、签名有效、不凭空变钱
```

第 ⑤ 条是**内存池层面的双花防护**——"**先到先得**"：同一笔钱的两笔冲突交易，节点只接受先看到的那一笔。

但请注意这只是每个节点**各自**的临时判断。不同的节点可能先看到不同的那一笔。
实验 12 把这一点演示得很清楚：

```text
   Bob 的内存池：  ['甲']
   Carol 的内存池：['乙']
   每个节点只认**自己先看到的那一笔**，后到的那笔因为"花了同一枚币"被拒之门外。
   此刻 Bob 的钱包显示余额 50.00，Carol 的钱包也显示 50.00 —— 两个人都以为自己收到钱了！
```

最终的裁决只能来自区块链：哪一笔先被挖进最长链，哪一笔算数。**内存池里的交易没有任何保障。**

第 ⑥ 条里，输入引用的交易可以已经在区块里，也可以**还在内存池里**——
也就是说可以花一笔"尚未确认的钱"（比如刚收到的找零）。矿工打包时会保证父交易排在子交易前面。

### 交易替换

第 ⑤ 条有一个例外，对应第 6 章末尾讲的 `nSequence`：如果新交易花的是和池里某笔交易**完全相同**的一组输入，
并且序列号更高（`is_newer_than`），它就**替换**掉旧的那笔。这是 0.1.x 独有的功能，后来被禁用了。

```python
                    if not tx.is_newer_than(old_tx):
                        return self._err("AcceptTransaction: 与池内交易冲突（双花）")
```

## 11.4　内存池怎么和区块链配合

**新区块到来时**（`blockchain.py` 的 `_add_to_block_index` 末尾）：区块里的交易已经上链了，
把它们从内存池里删掉。

**链重组时**：

* 被断开的区块里的交易 → **放回**内存池（"复活"），等着被重新打包；
* 新连接的区块里的交易 → 从内存池**删除**。

```python
        if self.mempool is not None:
            for tx in resurrect:                # 被断开的区块里的交易放回内存池
                self.mempool.accept(tx, check_inputs=False)
            for tx in removed_from_pool:        # 已经上链的交易从内存池删除
                self.mempool.remove(tx)
```

"复活"时用 `check_inputs=False` 跳过了输入检查——这些交易之前已经被完整验证过。
其中如果有现在已经无效的（比如和新链上的交易冲突），矿工打包时的检查会把它筛掉。

**节点重启时**：内存池清空了。钱包会把自己那些"还没进区块"的交易重新放回去
（`wallet.reaccept_wallet_transactions()`，第 12 章），否则它们就再也没人打包了。

## 11.5　手续费：v0.1.5 的规则

第 6 章说过：手续费 = 输入总额 − 输出总额，归打包这笔交易的矿工。那么矿工对手续费有什么要求？

规则在 `tx.py` 的 `get_min_fee` 里，和原版逐行对应：

```python
    def get_min_fee(self, f_discount: bool = False) -> int:
        n_bytes = self.get_serialize_size()
        min_fee = (1 + n_bytes // 1000) * params.CENT       # ① 每"开始的"1000 字节收 0.01 BTC
        if f_discount and n_bytes < 10000:
            min_fee = 0                                     # ② 有折扣且小于 10K 字节：免费
        if min_fee < params.CENT:
            for txout in self.vout:
                if txout.n_value < params.CENT:             # ③ 只要有一个输出小于 0.01 BTC
                    min_fee = params.CENT                   #    就至少收 0.01
                    break
        return min_fee
```

谁来执行？**矿工，在打包的时候**（`miner.py`）：

```python
                    # 每个区块的前 100 笔交易，只要小于 10K 字节就免费；否则每千字节 0.01
                    min_fee = tx.get_min_fee(f_discount=len(vtx) < 100)
                    ...
                    fee = self.chain.connect_inputs(tx, test_pool_tmp, prev.n_height + 1, min_fee, mem_txs)
                    if fee is None:
                        continue                # 手续费不够（或交易无效）：这个区块不带它
```

翻译成人话：

> * 普通的小交易（几百字节）：**免费**——只要这个区块里排在它前面的交易不到 100 笔；
> * 区块里第 100 笔之后的交易，或者特别大的交易（≥ 10KB）：每千字节 0.01 BTC；
> * 含有"粉尘"输出（小于 0.01 BTC）的交易：至少 0.01 BTC。

**内存池不检查手续费**——再抠门的交易也能进池、也会被转发，只是矿工不打包它。
`tests/test_miner.py::test_fee_threshold_is_enforced_by_the_miner_not_the_mempool` 验证了这一点。

还要注意：这只是**矿工的打包策略**，不是**共识规则**。一个区块里包含了零手续费的交易，其他节点照样接受这个区块。
每个矿工原则上可以自己决定收什么样的交易。

### 这套规则在防什么

2009 年比特币没有价格，区块几乎是空的。手续费的目的不是赚钱，而是**防止有人用垃圾把网络灌满**：

* **按字节收费**：交易越大，占用所有节点的带宽和磁盘越多；
* **粉尘规则**：如果允许免费创建无数个 0.00000001 BTC 的输出，UTXO 账本会被无限撑大，
  而每个全节点都得永久保存这些"花起来比它自己还贵"的输出；
* **前 100 笔免费**：给正常用户保留一条免费通道，同时限制了"免费空间"的总量。

### 钱包怎么凑手续费

钱包在创建交易时并不知道最终要付多少手续费——因为手续费取决于交易的字节数，而字节数要签完名才知道。
所以是一个循环（`wallet.py` 的 `create_transaction`，原版同构）：

```python
            fee = self.transaction_fee              # 从用户设置的手续费开始（默认 0）
            while True:
                ...选币、组装、签名...
                min_fee = tx.get_min_fee(f_discount=True)
                if fee < min_fee:
                    fee = min_fee                   # 不够：加到最低要求，重来一轮
                    continue
                return WalletTx(tx, ...), fee
```

实验 10 的第 7 步演示了手动设置 0.05 的手续费后，矿工的 coinbase 从 50.00 变成了 50.05。

## 11.6　后来的故事：从"门票"到"竞价"

v0.1.5 的手续费规则有几个结构性的问题，每一个后来都引发了一次演化：

| v0.1.5 的做法 | 问题 | 后来怎么变的 |
|---|---|---|
| 以 BTC 计价的固定费率（0.01/KB） | 0.01 BTC 在 2009 年一文不值，到 2013 年值好几美元——币价一涨，固定费率就荒唐了 | 2011 年起几次手动下调；最终改为完全由市场决定 |
| 小交易免费 | 任何人都可以免费往网络里灌交易 | 2010 年引入"优先级"（币龄 × 金额 ÷ 体积）限制免费通道；2016~2017 年彻底取消免费交易 |
| 只有"够不够最低费"的二值判断 | 区块装满之后，谁该被打包没有答案 | 矿工改为按**费率**（每字节多少聪）从高到低排序打包，形成竞价市场 |
| 粉尘阈值硬编码为 0.01 BTC | 和实际成本无关 | 改为按"花掉这个输出需要多少字节的手续费"动态计算（今天约 546 聪） |
| 内存池无上限 | 可被用来耗尽节点内存 | 2016 年起内存池有容量上限，满了就踢掉费率最低的 |

这条线索的方向很清楚：**手续费的角色，从"防垃圾的门票"变成了"区块空间的竞拍价"。**

这背后有一个长期的经济学问题。区块补贴每四年减半，大约 2140 年归零。
到那时，**手续费将是矿工唯一的收入**，也就是整个网络安全性的唯一经费来源。
纯靠手续费的竞价市场能不能养活足够的算力？这是一个至今没有定论的开放问题（第 15 章）。

## 本章小结

* 内存池 = 已验证但未上链的交易的候车室；只在内存里，各节点不一致，**不属于共识**。
* 准入 = 格式检查 + 查重 + 池内双花检查（**先到先得**）+ 输入检查（存在、未花、成熟、签名、不超支）。
* 新区块到来时，已上链的交易移出内存池；重组时，被断开的交易放回、新确认的移出。
* v0.1.5 的手续费：**小交易免费**（每区块前 100 笔）、大交易每 KB 0.01、含粉尘输出至少 0.01；
  由**矿工打包时**执行，内存池不检查，也不是共识规则。
* 手续费后来演化为按费率竞价的市场，并将在补贴归零后成为网络安全的唯一经费。
