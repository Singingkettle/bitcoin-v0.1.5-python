# 附录 A　术语表

按拼音排序。括号里是英文原文和源码中对应的名字；最后的数字是首次详细讲解的章节。

| 术语 | 解释 | 章 |
|---|---|---|
| **51% 攻击** | 掌握全网过半算力的攻击者可以（只可以）撤销并重花自己近期的交易 | 10 |
| **ASIC** | 专门为计算 SHA-256 设计的芯片，效率比普通 CPU 高出很多个数量级 | 15 |
| **Base58 / Base58Check** | 去掉了 `0 O I l` 的 58 个字符的编码；Check 版末尾带 4 字节校验和（`base58.py`） | 5 |
| **BIP** | Bitcoin Improvement Proposal，比特币改进提案 | 16 |
| **比特（bit）/ 字节（byte）** | 一个 0 或 1；8 个比特。两个十六进制字符 = 1 字节 | 2 |
| **变长整数（CompactSize）** | 小数字占 1 字节、大数字占 3/5/9 字节的整数编码（`ser_compact_size`） | 2 |
| **不可能三角** | 去中心化、安全、可扩展性三者难以兼得 | 15 |
| **coinbase 交易** | 每个区块的第一笔交易，输入为空，凭空产生区块奖励。比特币唯一的发行方式（`is_coinbase`） | 6 |
| **成熟期** | coinbase 产生的币要等 100 个确认（钱包里是 120 个）才能花（`COINBASE_MATURITY`） | 9、12 |
| **创世块（genesis block）** | 第 0 号区块，写死在源码里（`build_genesis_block`） | 8 |
| **重组（reorganize）** | 最佳链从一条分支切换到另一条更长的分支（`reorganize`） | 10 |
| **大端 / 小端** | 多字节整数里，高位字节在前 / 低位字节在前。比特币几乎全用小端 | 2 |
| **DER** | 一种标准的二进制编码格式，ECDSA 签名用它打包 (r, s)，以 `30` 开头 | 4 |
| **地址** | Base58Check( `00` + 公钥哈希 )，以 `1` 开头 | 5 |
| **定稿（final）** | `nLockTime` 已过或所有输入的 `nSequence` 拉满；未定稿的交易可被替换（`is_final`） | 6 |
| **ECDSA** | 椭圆曲线数字签名算法 | 4 |
| **分叉（fork）** | 同一高度出现了两个（或更多）合法区块，链暂时分成两支 | 10 |
| **分帧（framing）** | 把 TCP 字节流切回一条条消息（`parse_messages`） | 13 |
| **粉尘（dust）** | 金额小到花掉它的手续费比它本身还贵的输出；v0.1.5 的阈值是 0.01 BTC | 11 |
| **getblocks / inv / getdata** | "后面的区块你有吗" / "我有这些" / "请发给我"——同步与广播的三种核心消息 | 13 |
| **工作量证明（PoW）** | 找到使区块哈希 ≤ 目标值的 nonce；难找易验，无法伪造 | 3、9 |
| **公钥 / 私钥** | 私钥是一个随机的 256 位整数；公钥 = 私钥 × G。私钥签名，公钥验签（`CKey`） | 4 |
| **公钥哈希（Hash160）** | RIPEMD160(SHA256(公钥))，20 字节（`hash160`） | 3、5 |
| **孤块（orphan block）** | 父块尚未收到的区块，先暂存（`map_orphan_blocks`）。注意：后来这个词也常被用来指"被重组掉的区块"，两个意思不同 | 10 |
| **孤儿交易** | 引用了尚未见过的父交易的交易 | 13 |
| **哈希函数** | 任意长度输入 → 固定长度输出；确定、雪崩、单向、抗碰撞 | 3 |
| **hash256 / Hash()** | 两次 SHA-256。用于区块哈希、交易哈希、校验和 | 3 |
| **hashtype / SIGHASH** | 签名末尾的一个字节，说明签名覆盖交易的哪些部分（ALL/NONE/SINGLE/ANYONECANPAY） | 7 |
| **激励相容** | 制度设计使得个体追求私利的行为恰好有利于整体 | 15 |
| **减半（halving）** | 区块补贴每 21 万个区块减半 | 9 |
| **脚本（script）** | 比特币的锁和钥匙所用的栈式小语言，没有循环（`script.py`） | 7 |
| **节点（node）** | 运行比特币软件、保存并验证区块链的一台计算机 | 13 |
| **聪（satoshi）** | 最小单位，1 BTC = 100,000,000 聪。程序里所有金额都是聪的整数 | 2 |
| **离散对数问题** | 已知 G 和 k·G 求 k；椭圆曲线上没有高效解法，是私钥安全的基础 | 4 |
| **邻居（peer）** | 与本节点有直接 TCP 连接的其他节点（`CNode`） | 13 |
| **零确认** | 已广播但尚未进入任何区块的交易。不安全 | 11、12 |
| **魔数（magic）** | 每条网络消息开头的 4 字节固定值 `f9beb4d9`（`MESSAGE_START`） | 13 |
| **默克尔树 / 默克尔根** | 交易哈希两两配对逐层哈希形成的树；树根写在区块头里（`build_merkle_tree`） | 8 |
| **模运算 / 有限域** | 只保留余数的算术；模一个质数时四则运算封闭 | 4 |
| **nBits** | 区块头里 4 字节的难度目标压缩编码（`compact_to_target`） | 9 |
| **难度调整** | 每 2016 个区块按实际出块速度调整目标值（`get_next_work_required`） | 9 |
| **内存池（mempool）** | 已验证、未上链的交易的暂存区（`MemPool`） | 11 |
| **nonce** | 区块头里供矿工反复修改的 4 字节字段；也泛指"只用一次的数" | 9 |
| **nLockTime / nSequence** | 交易的锁定时间 / 输入的序列号，用于"可替换交易" | 6 |
| **女巫攻击（Sybil attack）** | 伪造大量身份来操纵基于"人数"的投票 | 1 |
| **opcode（操作码）** | 脚本里的一条指令，如 `OP_DUP`、`OP_CHECKSIG` | 7 |
| **P2P** | 点对点网络，没有中心服务器 | 13 |
| **P2PK** | 付给公钥：`<公钥> OP_CHECKSIG` | 7 |
| **P2PKH** | 付给公钥哈希（即付给地址）：`OP_DUP OP_HASH160 <哈希> OP_EQUALVERIFY OP_CHECKSIG` | 7 |
| **前序输出（prevout / COutPoint）** | 输入里的指针：(某笔交易的哈希, 第几个输出) | 6 |
| **钱包** | 保管私钥、跟踪与自己有关的交易的软件。币不在钱包里 | 12 |
| **区块（block）** | 80 字节区块头 + 一批交易（`CBlock`） | 8 |
| **区块定位器（block locator）** | 前密后疏的区块哈希列表，用于向对方描述自己的链（`CBlockLocator`） | 13 |
| **区块索引（CBlockIndex）** | 每个已知区块在内存中的目录项，用 `pprev`/`pnext` 连成树 | 8、10 |
| **确认数（confirmations）** | 交易所在区块的深度：刚进区块为 1，每多一个后继区块加 1 | 10 |
| **RFC 6979** | 从私钥和消息确定性地推导签名随机数 k 的标准，避免 k 重复 | 4 |
| **RIPEMD-160** | 输出 160 比特的哈希函数，用于生成地址（`ripemd160.py`） | 3 |
| **scriptPubKey / scriptSig** | 输出上的"锁" / 输入里的"钥匙" | 7 |
| **secp256k1** | 比特币使用的椭圆曲线 y² = x³ + 7 (mod p) | 4 |
| **SHA-256** | 输出 256 比特的哈希函数，比特币的主力 | 3 |
| **SignatureHash** | 计算"签名到底签的是什么"的函数：清空 scriptSig、填入锁、附上 hashtype 后的哈希 | 7 |
| **手续费** | 输入总额 − 输出总额，归打包该交易的矿工；交易里没有单独的字段 | 6、11 |
| **双花（double spend）** | 同一笔钱被花两次。比特币要解决的核心问题 | 1 |
| **SPV** | 简化支付验证：只存区块头，用默克尔证明验证交易 | 8 |
| **target（目标值）** | 区块哈希必须小于等于的那个 256 位数；越小越难 | 9 |
| **通缩 / 固定总量** | 总量上限约 2100 万，来自"50 起步、每 21 万块减半"的等比数列 | 9、15 |
| **椭圆曲线** | 满足 y² = x³ + ax + b 的点的集合，点之间可定义加法 | 4 |
| **UTXO** | Unspent Transaction Output，未花费的交易输出。比特币里的"钱"就是 UTXO | 6 |
| **序列化** | 按固定规则把对象变成字节串（`DataStream`） | 2 |
| **雪崩效应** | 输入微小变化导致哈希输出约一半的比特翻转 | 3 |
| **延展性（malleability）** | 第三方可在不破坏签名的前提下改变交易 ID；2017 年由 SegWit 解决 | 16 |
| **找零** | UTXO 只能整个花掉，多出的部分作为一个新输出付回给自己 | 6、12 |
| **整笔标记（fSpent）** | v0.1.5 钱包每笔交易只有一个"已花"标志 | 12 |
| **最长链原则** | 分叉时认工作量最大（v0.1.5 中为高度最高）的那条链 | 10 |
