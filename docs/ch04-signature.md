# 第 4 章　数字签名与椭圆曲线

> **本章目标**：理解"私钥—公钥—签名"这套机制为什么管用。我们会从钟面上的算术讲起，
> 一路走到亲手验证中本聪 2009 年的真实签名。这是全教程数学最多的一章，但用到的只有加减乘除和余数。
>
> **对应源码**：[bitcoin/key.py](../bitcoin/key.py)　　**实验**：[labs/lab03_elliptic_curve.py](../labs/lab03_elliptic_curve.py)

## 4.1　我们想要什么

第 1 章说过，去掉银行之后要解决的第一个问题是"冒充"：怎么证明一条"我把钱转给小红"的消息真是钱的主人发的？

现实世界里我们用签名或印章。但数字世界里的任何东西都可以被完美复制——
你把签名的图片贴在一条消息上，别人就能把它抠下来贴到另一条消息上。

我们需要的"数字签名"必须同时满足三条：

1. **只有本人能签**：没有某个秘密，就造不出有效的签名；
2. **所有人都能验**：验证签名不需要知道那个秘密；
3. **签名和消息绑死**：对消息 A 的签名，用在消息 B 上无效；消息哪怕改一个标点，签名就失效。

第 2 条和第 1 条看上去是矛盾的：验证的人既然不知道秘密，凭什么判断签名的人知道秘密？

答案是用**一对**数学上有关联的钥匙：

* **私钥**（private key）：一个只有你知道的秘密数字，用来**签名**；
* **公钥**（public key）：由私钥算出来的另一个数，可以公开给全世界，用来**验证**。

关键在于：**从私钥算公钥很容易，从公钥反推私钥做不到。** 这又是一个"单向"的东西，和哈希函数的精神一致。
比特币用来实现这个单向关系的数学工具，叫**椭圆曲线**。

## 4.2　第一步：钟面上的算术（模运算）

钟面上，10 点再过 5 个小时是 3 点，不是 15 点。因为钟面"满 12 就归零"：

```text
(10 + 5) mod 12 = 3          "mod" 读作"模"，意思是"除以 12 取余数"
```

这就是**模运算**：所有的计算结果都只保留除以某个数（叫"模数"）之后的余数。

在"模 17"的世界里，数字只有 0, 1, 2, …, 16 这 17 个：

```text
13 + 9 = 22 -> 22 mod 17 = 5
13 × 9 = 117 -> 117 mod 17 = 15        （117 = 6×17 + 15）
 3 - 8 = -5 -> -5 mod 17 = 12          （往回绕：-5 + 17 = 12）
```

加、减、乘都没问题。那**除法**呢？

在普通算术里，"除以 5"就是"乘以 5 的倒数 1/5"，而 1/5 的定义是"和 5 相乘得 1 的那个数"。
在模 17 的世界里我们照搬这个定义：找一个数 x，使得 5 × x mod 17 = 1。
试一下：5 × 7 = 35 = 2×17 + 1，所以 **5 的倒数是 7**。于是：

```text
3 ÷ 5 (mod 17)  =  3 × 7 mod 17  =  21 mod 17  =  4
验算：4 × 5 = 20 -> 20 mod 17 = 3  ✓
```

一个重要的事实（这里不证明）：**只要模数是质数，除了 0 以外的每个数都有倒数。**
于是在"模一个质数 p"的世界里，加减乘除四则运算全都能做，而且结果永远落在 0 到 p−1 之间。
数学家把这样的世界叫做**有限域**，记作 F_p。

Python 里求倒数只要一行：`pow(5, -1, 17)` 得到 `7`。

> 为什么要用有限域，而不用普通的实数？因为计算机没法精确地表示实数（只能存有限位小数），
> 而密码学要求每一步计算都**绝对精确**、在谁的电脑上算都一样。有限域里只有整数，没有误差。

## 4.3　第二步：椭圆曲线

**椭圆曲线**是满足这样一个方程的所有点 (x, y) 的集合：

```text
y² = x³ + ax + b
```

比特币用的那条曲线 a = 0、b = 7，方程特别简单：

```text
y² = x³ + 7
```

（名字里有"椭圆"只是历史原因——它源于计算椭圆周长的积分，曲线本身一点也不像椭圆。）

如果在实数上画出来，它是一条光滑的、左边封口右边张开的曲线，并且上下对称（因为 y 和 −y 同时满足方程）。

### 点的"加法"

椭圆曲线最神奇的地方在于：可以在曲线上的点之间定义一种"加法"。几何上的规则是这样的：

> 要算 P + Q：过 P、Q 两点画一条直线，它一定会和曲线交于第三个点；
> 把这第三个点**上下翻转**（y 变成 −y），得到的点就是 P + Q。

```text
             │          · R'                 P、Q 连线交曲线于 R'
             │        ·                      R' 关于 x 轴翻转得到 R
        Q ·  │     ·                         定义 P + Q = R
      P ·────┼──·──────────
             │    ·
             │       · R = P + Q
```

如果 P 和 Q 是同一个点（算 P + P），就用曲线在 P 点的**切线**代替"连线"。

用高中的解析几何可以把这个几何规则写成公式。设 P = (x₁, y₁)，Q = (x₂, y₂)：

```text
斜率   k = (y₂ − y₁) / (x₂ − x₁)          （P ≠ Q 时，两点连线的斜率）
       k = 3x₁² / (2y₁)                   （P = Q 时，切线的斜率——对方程求导得到）

结果   x₃ = k² − x₁ − x₂
       y₃ = k(x₁ − x₃) − y₁
```

还有一个特殊情况：如果 P 和 Q 上下对称（x 相同、y 相反），连线是竖直的，和曲线没有第三个交点。
这时规定结果是一个特殊的"**无穷远点**"，记作 O。它在这种加法里扮演 **0** 的角色：P + O = P。

这种加法满足交换律和结合律，和普通加法的性质一样（证明略）。

### 搬到有限域里

密码学用的椭圆曲线不在实数上，而在有限域 F_p 上：x、y 只取 0 到 p−1 的整数，
方程变成 `y² ≡ x³ + 7 (mod p)`，上面公式里的除法换成"乘以模逆元"。
这时"曲线"不再是一条线，而是一堆散落的点，几何直觉没有了，**但公式原封不动地成立**。

实验 3 里的玩具曲线 `y² = x³ + 7 (mod 17)` 一共只有 17 个点（加上无穷远点共 18 个）：

```text
(1,5) (1,12) (2,7) (2,10) (3,0) (5,8) (5,9) (6,6) (6,11)
(8,3) (8,14) (10,2) (10,15) (12,1) (12,16) (15,4) (15,13)
```

实验里的点加法函数只有十几行，就是把上面的公式直译成 Python：

```python
    def add(P, Q):
        if P is None:
            return Q
        if Q is None:
            return P
        (x1, y1), (x2, y2) = P, Q
        if x1 == x2 and (y1 + y2) % p == 0:
            return None                                     # P + (-P) = 0
        if P == Q:
            k = (3 * x1 * x1 + a) * pow(2 * y1, -1, p) % p  # 切线的斜率
        else:
            k = (y2 - y1) * pow(x2 - x1, -1, p) % p         # 两点连线的斜率
        x3 = (k * k - x1 - x2) % p
        return x3, (k * (x1 - x3) - y1) % p
```

## 4.4　第三步：数乘与单向性

有了加法就有了"乘以一个整数"：

```text
k·G = G + G + … + G      （k 个 G 相加）
```

从点 G = (6, 6) 出发不断自加，会得到（实验 3 的真实输出）：

```text
G, 2G, 3G, …  =  (6,6) (1,5) (8,14) (2,10) (10,15) (5,9) (15,4) (12,1) (3,0)
                 (12,16) (15,13) (5,8) (10,2) (2,7) (8,3) (1,12) (6,11)  O  (6,6) …
```

走遍了全部 17 个点，第 18 步到达无穷远点 O，第 19 步又回到 G。我们说点 G 的**阶**是 18。

注意这个序列看起来是"乱跳"的：从 k 看不出 k·G 会落在哪里，相邻的 k 对应的点毫无规律。

**现在到了关键的地方。**

* **已知 k，求 k·G：很快。** 不需要真的加 k 次。用"倍加法"：算出 G、2G、4G、8G……（每次自己加自己），
  再按 k 的二进制展开把需要的几项加起来。k 是一个 256 比特的数时，总共只要几百次点加法，电脑一瞬间就算完。

  ```python
      def mul(n, P):
          result = None
          while n:
              if n & 1:                       # n 的二进制最低位是 1：把当前的 P 加进结果
                  result = add(result, P)
              P = add(P, P)                   # P 翻倍
              n >>= 1                         # 看 n 的下一个二进制位
          return result
  ```

* **已知 G 和 k·G，反求 k：做不到。** 除了从 1 开始一个一个试，人类目前不知道任何本质上更快的办法
  （已知最好的算法也需要大约 √n 步）。这叫**椭圆曲线离散对数问题**。

玩具曲线只有 18 种可能，当然一试就中。而比特币用的真曲线——

## 4.5　secp256k1

比特币用的曲线有个正式的名字叫 **secp256k1**，它的参数是公开的标准：

```text
方程       y² = x³ + 7  (mod p)
模数 p   = 2²⁵⁶ − 2³² − 977                                        一个 256 位的质数
基点 G   = (0x79BE667E F9DCBBAC 55A06295 CE870B07 029BFCDB 2DCE28D9 59F2815B 16F81798,
            0x483ADA77 26A3C465 5DA4FBFC 0E1108A8 FD17B448 A6855419 9C47D08F FB10D4B8)
G 的阶 n = 0xFFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFE BAAEDCE6 AF48A03B BFD25E8C D0364141
         ≈ 1.158 × 10⁷⁷
```

于是：

> **私钥** = 一个 1 到 n−1 之间的随机整数 d（256 比特）
> **公钥** = 点 Q = d·G（一个坐标 (x, y)，各 256 比特）

从 d 算 Q：几百次点加法，不到一毫秒。
从 Q 反推 d：需要大约 √n ≈ 2¹²⁸ ≈ 3.4×10³⁸ 步。全世界所有的计算机加在一起算到太阳熄灭也算不完。

**你的全部比特币财产，就维系在这个"算不完"上。**

在 v0.1.5 里，公钥被序列化成 65 个字节：1 字节前缀 `04` + 32 字节 x + 32 字节 y。
（后来的版本引入了 33 字节的"压缩公钥"：因为曲线上下对称，知道 x 就只有两个可能的 y，多记一个比特就够了。）

## 4.6　第四步：ECDSA 签名

有了私钥 d 和公钥 Q = d·G，怎么签名？比特币用的算法叫 **ECDSA**（椭圆曲线数字签名算法）。

设要签的消息的哈希是 z（一个 256 比特的整数）。

**签名**（需要私钥 d）：

```text
1. 随机选一个一次性的秘密数 k（1 到 n−1 之间）
2. 算点 R = k·G，取它的 x 坐标：  r = R.x mod n
3. 算  s = (z + r·d) / k  mod n          （"除以 k"就是乘以 k 在模 n 下的倒数）
4. 签名就是这一对数 (r, s)
```

**验证**（只需要公钥 Q）：

```text
1. 算  u₁ = z / s mod n，   u₂ = r / s mod n
2. 算点 P = u₁·G + u₂·Q
3. 如果 P 的 x 坐标（mod n）等于 r，签名有效
```

**为什么这样验证是对的？** 把 Q = d·G 代进去：

```text
P = u₁·G + u₂·Q
  = (z/s)·G + (r/s)·d·G
  = ((z + r·d) / s)·G
```

而签名时 s = (z + r·d)/k，移项得 (z + r·d)/s = k。所以 **P = k·G = R**，它的 x 坐标当然就是 r。✓

**为什么没有私钥就签不了？** 伪造者要凑出一对 (r, s) 使验证等式成立。s 的算式里有 d（私钥），
他不知道 d，也没法从 Q 反推 d，凑不出来。

**为什么签名和消息绑死？** z 出现在算式里。消息变了，z 就变了，原来的 (r, s) 就不再满足等式。

实验 3 的第 9~10 步用几十行纯 Python 手写了签名和验签，并且和项目实际使用的 `ecdsa` 库互相验证：
库签的名，手写代码能验过；手写代码签的名，库也能验过。

### ⚠️ 那个一次性的 k 是要命的

如果同一个私钥的两次签名用了**同一个 k**，任何人都能把私钥算出来：

```text
s₁ = (z₁ + r·d)/k，  s₂ = (z₂ + r·d)/k        （k 相同，所以 r 也相同）
相减：s₁ − s₂ = (z₁ − z₂)/k   =>   k = (z₁ − z₂)/(s₁ − s₂)
有了 k，再从 s₁ 的式子解出：  d = (s₁·k − z₁)/r
```

这不是纸上谈兵。2010 年索尼 PS3 的主签名私钥就是这样泄露的（他们的 k 是个固定的常数）；
2013 年，安卓系统的随机数发生器有缺陷，导致一批比特币钱包的私钥被人算出、币被偷走。

本项目（以及现代的比特币软件）用 **RFC 6979** 规定的办法从根上解决：k 不再随机选，
而是由"私钥 + 消息"通过哈希确定性地算出来。不同的消息自然得到不同的 k，而且不依赖任何随机数发生器。

## 4.7　源码导读：key.py

[bitcoin/key.py](../bitcoin/key.py) 只有 60 行，因为椭圆曲线运算交给了纯 Python 的 `ecdsa` 库
（原版 C++ 用的是 OpenSSL）。`CKey` 这个类名沿用自原版：

```python
class CKey:
    @classmethod
    def generate(cls) -> "CKey":
        """MakeNewKey()：随机生成一把新私钥。"""
        return cls(SigningKey.generate(curve=SECP256k1))

    def get_pubkey(self) -> bytes:
        """GetPubKey()：65 字节非压缩公钥。"""
        return b"\x04" + self._sk.get_verifying_key().to_string()

    def sign(self, digest: bytes) -> bytes:
        """Sign()：对一个 32 字节的摘要签名，返回 DER 编码的签名。"""
        return self._sk.sign_digest_deterministic(
            digest, hashfunc=hashlib.sha256, sigencode=sigencode_der
        )
```

两个细节：

* **签的是摘要，不是消息本身。** 传进来的 `digest` 是 32 字节的哈希值。
  对比特币交易来说，这个摘要怎么算是一件相当讲究的事，第 7 章细讲。
* **DER 编码。** 签名是两个 256 比特的数 (r, s)，按一种叫 DER 的标准格式打包成约 70~72 个字节：

  ```text
  30 <总长>  02 <r 的长度> <r ……>  02 <s 的长度> <s ……>
  ```

  以后你在交易的十六进制里看到 `3044022…` 或 `3045022…` 这样的开头，那就是一个签名。

验证函数有一条重要的纪律：

```python
    @staticmethod
    def verify_with_pubkey(pubkey: bytes, digest: bytes, sig_der: bytes) -> bool:
        """……任何格式错误都只返回 False，绝不抛异常——
        因为公钥和签名都来自网络上的陌生人，垃圾数据不能让节点崩溃。"""
        try:
            vk = VerifyingKey.from_string(pubkey, curve=SECP256k1)
            return vk.verify_digest(sig_der, digest, sigdecode=sigdecode_der)
        except BadSignatureError:
            return False
        except Exception:       # 公钥不在曲线上、DER 结构损坏等
            return False
```

## 本章小结

* 数字签名 = 只有私钥能签 + 任何人用公钥能验 + 和消息绑死。
* 有限域 F_p：模一个质数的四则运算，结果永远是 0 到 p−1 的整数，没有误差。
* 椭圆曲线上的点可以"相加"；**k·G 算起来很快，反过来由 k·G 求 k 做不到**——这是全部安全性的来源。
* 私钥 = 随机的 256 比特整数；公钥 = 私钥·G。
* ECDSA 签名是一对数 (r, s)，验证时算 (z/s)·G + (r/s)·Q，看 x 坐标是否等于 r。
* 签名里的随机数 k **绝不能重复使用**，否则私钥泄露。

## 思考题

1. 在模 17 下，3 的倒数是多少？2 ÷ 3 等于多少？
2. 私钥有大约 2²⁵⁶ 种可能。有人担心："会不会两个人随机生成了同一把私钥？"请估计一下这个概率。
3. 验证签名时完全不需要私钥。请用自己的话解释，为什么这不会让伪造签名变得容易。

<details><summary>参考答案</summary>

1. 3 × 6 = 18 = 17 + 1，所以 3 的倒数是 6。2 ÷ 3 = 2 × 6 mod 17 = 12。验算：12 × 3 = 36 = 2×17 + 2 ✓。
2. 根据生日悖论，要生成约 √(2²⁵⁶) = 2¹²⁸ ≈ 3.4×10³⁸ 把私钥才可能出现一次重复。
   即使全世界 80 亿人每人每秒生成一百万把，也需要约 10¹⁵ 年——是宇宙年龄的十万倍。可以放心地认为不会发生。
3. 验证只是"检查一个等式是否成立"，而伪造需要"构造出使等式成立的 (r, s)"。
   这就像验算一道题的答案很容易，但不会解题的人凑不出正确答案。
   等式的结构保证了：要凑出 s，就必须知道 d（或者能解离散对数）。
