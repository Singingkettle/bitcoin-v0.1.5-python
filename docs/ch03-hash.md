# 第 3 章　哈希函数：数据的指纹

> **本章目标**：理解哈希函数的四个性质，以及它们各自在比特币里派什么用场。
> 哈希函数是比特币里用得最多的零件——地址、交易 ID、区块 ID、默克尔树、挖矿，全都靠它。
>
> **对应源码**：[bitcoin/hashes.py](../bitcoin/hashes.py)、[bitcoin/ripemd160.py](../bitcoin/ripemd160.py)
> 　　**实验**：[labs/lab02_hash.py](../labs/lab02_hash.py)

## 3.1　什么是哈希函数

哈希函数（hash function）是这样一台机器：

```text
   任意长度的数据  ──►  [ 哈希函数 ]  ──►  固定长度的一小段数据（"哈希值"、"摘要"、"指纹"）
```

比特币主要用的是 **SHA-256**（Secure Hash Algorithm，输出 256 比特 = 32 字节），
由美国国家标准与技术研究院在 2001 年公布，全世界的密码学家研究了二十多年，至今没有发现实用的攻击方法。

```python
>>> import hashlib
>>> hashlib.sha256(b"bitcoin").hexdigest()
'6b88c087247aa2f07ee1c5956b8e1a9f4c7f892a70e324f1bb3d161e05ca107b'
```

不管你喂给它的是空字符串、一个字母、还是一部 100 万字的小说，出来的永远是 64 个十六进制字符。

它内部是怎么算的，本教程不展开（大体上是把数据切成 64 字节的小块，每一块都和当前的中间状态一起，
经过 64 轮移位、异或、模加的"搅拌"）。对理解比特币来说，你只需要把它当成一个**黑盒子**，
牢牢记住这个黑盒子的四个性质。

## 3.2　性质一：确定性

同样的输入，永远得到同样的输出——不管在谁的电脑上、哪一年、用什么编程语言算。

这听起来是废话，但它是"全世界的节点能对同一笔交易算出同一个 ID"的前提。

## 3.3　性质二：雪崩效应

输入只要改变一点点（哪怕一个比特），输出就面目全非：

```text
"I owe Alice 10 BTC"  ->  e299c9cd75dfe38aaae6e9ccaf5187f23555275c0fa3ed52b14795a1aa92c49a
"I owe Alice 11 BTC"  ->  cbb3a35ef4a7ffd18afb9e34903cac363caa928ab08a630a3d4a54e116e1b399
```

实验 2 会帮你数出来：这两个输出的 256 个比特里有 127 个不同——几乎正好一半，和两个毫无关系的随机数一样。

也就是说，**输出看起来完全是随机的**，你没法通过观察输出来猜测输入的任何信息，
也没法"微调"输入来让输出朝你想要的方向变一点点。

**在比特币里的用途**：防篡改。区块头里存着全部交易的"指纹"，任何人改动任何一笔交易的任何一个比特，
指纹就完全变了，立刻被发现。

## 3.4　性质三：单向性（抗原像）

给你输入，算输出，一瞬间；给你输出，想找到一个能产生它的输入——**除了一个一个去试，没有任何更好的办法。**

256 比特的输出一共有 2²⁵⁶ ≈ 1.16×10⁷⁷ 种可能。这个数有多大？

* 可观测宇宙里的原子总数大约是 10⁸⁰ 个，和它只差三个数量级；
* 假设你有一台每秒能算一百亿亿次（10¹⁸）哈希的机器——比今天整个比特币网络的总算力还强，
  让它从宇宙大爆炸算到现在（约 4×10¹⁷ 秒），总共也只能试 4×10³⁵ 次，
  连全部可能性的一万亿亿亿亿分之一都不到。

**在比特币里的用途**：

* **地址**是公钥的哈希。只看到地址，没人能反推出公钥（更别说私钥）。
* **挖矿**。这是单向性最巧妙的一次应用，下一节单独讲。

## 3.5　从单向性到"工作量证明"

既然没法反推，那么如果我提出一个要求：

> 请找一个数字 n，使得 `sha256("hello" + n)` 的结果以 `0000` 开头。

你唯一的办法就是 n = 0, 1, 2, 3… 一个一个试。哈希值的每个十六进制位都像是均匀随机的，
开头 4 位恰好都是 0 的概率是 (1/16)⁴ = 1/65536，所以**平均**要试 65536 次。

实验 2 里的真实运行结果：

```text
想让 sha256('hello'+数字) 以 0000 开头，试了 60068 次才找到：hello60067
0000e49eab06aa7a6b3aef7708991b91a7e01451fd67f520b832b89b18f4e7de
```

注意这件事的**不对称性**：

* **找**到这个 60067，我试了六万次；
* 你**验证**它是不是对的，只需要算 **1 次**哈希。

而且我没法作弊——如果我没有真的去试那几万次，我就拿不出这个数字（除非运气好到离谱）。
于是"60067"这个数字本身，就成了**"我确实付出了大约六万次计算"的证明**。

这就是**工作量证明**（proof of work）的全部原理。把要求从"4 个 0"改成"5 个 0"，
工作量就变成 16 倍；改成"8 个 0"，就是 43 亿次。要求可以任意调节，第 9 章会详细讲。

## 3.6　性质四：抗碰撞

两个不同的输入恰好产生相同的输出，叫一次**碰撞**。

碰撞一定存在——输入有无穷多种，输出只有 2²⁵⁶ 种（高中学过的"抽屉原理"）。
但"存在"和"找得到"是两回事：要找到一对碰撞，即使用上最聪明的办法（利用"生日悖论"），
也需要大约 2¹²⁸ ≈ 3.4×10³⁸ 次尝试，依然是天文数字。迄今为止，全人类没有找到过哪怕一对 SHA-256 碰撞。

> **生日悖论**：一个班有 23 个人，至少两人同一天生日的概率就超过了 50%——比直觉小得多。
> 一般地，在 N 种可能里随机取，取到大约 √N 个时就很可能出现重复。
> 所以 256 比特的哈希，抗碰撞的强度是 √(2²⁵⁶) = 2¹²⁸，而不是 2²⁵⁶。

**在比特币里的用途**：正因为找不到碰撞，才可以放心地**用哈希值来代表数据本身**。
"交易 ID"就是交易的哈希，"区块 ID"就是区块头的哈希。全网用 32 个字节来指代一笔交易，
而不用担心有两笔不同的交易撞了 ID。

## 3.7　比特币里的两个"组合拳"

打开 [bitcoin/hashes.py](../bitcoin/hashes.py)，整个文件只有二十几行，核心是两个函数：

```python
def hash256(data: bytes) -> bytes:
    """Hash()：连续做两次 SHA-256。区块哈希、交易哈希、校验和都用它。"""
    return hashlib.sha256(hashlib.sha256(data).digest()).digest()


def hash160(data: bytes) -> bytes:
    """Hash160()：RIPEMD160(SHA256(data))。把 65 字节的公钥压成 20 字节，地址就是由它来的。"""
    return ripemd160(hashlib.sha256(data).digest())
```

**为什么要做两次 SHA-256？** 中本聪没有留下明确的解释。一般认为是一种"多穿一层防弹衣"的保守做法：
单次 SHA-256 存在一种叫"长度扩展"的结构性小弱点，套两层就彻底没有了；
万一将来 SHA-256 被发现某种弱点，两层也会比一层撑得久一些。代价只是多算一次，几乎可以忽略。

**为什么地址用 RIPEMD-160？** 为了短。RIPEMD-160 是 1996 年由比利时学者设计的另一种哈希函数，输出只有 160 比特（20 字节）。
先 SHA-256 再 RIPEMD-160，把 65 字节的公钥压成 20 字节，地址就能短不少。用两种不同家族的算法串联，
也是同样的保守思路：除非两种算法同时被攻破，否则地址就是安全的。

20 字节对"抗原像"来说绰绰有余（2¹⁶⁰ 种可能），中本聪认为足够了。

### 关于 ripemd160.py

Python 的 `hashlib` 依赖操作系统里的 OpenSSL 库，而较新的 OpenSSL 3 默认不再提供 RIPEMD-160。
所以本项目自带了一份**纯 Python 的 RIPEMD-160 实现**（[ripemd160.py](../bitcoin/ripemd160.py)，约 90 行），
`hashes.py` 里的 `ripemd160()` 会优先用系统的，用不了就自动退回自带的：

```python
def ripemd160(data: bytes) -> bytes:
    try:
        return hashlib.new("ripemd160", data).digest()
    except ValueError:
        return _ripemd_py.ripemd160(data)
```

如果你好奇一个哈希函数的内部长什么样，这 90 行是个很好的标本：
消息先被**填充**到 64 字节的整数倍，然后每 64 字节一组，经过左右两条各 80 步的流水线，
每一步就是几次加法、一次按位逻辑运算和一次循环移位。没有任何神秘的东西——
"单向性"来自于这些简单操作成百上千次的反复叠加，把输入的每一个比特的影响都扩散到了输出的每一个比特上。

`tests/test_hashes.py` 用算法作者公布的 9 组官方测试向量验证了这份实现，包括一个一百万字节的输入。

## 3.8　亲手算一次创世块的哈希

比特币的"区块哈希"就是对 80 字节的区块头做 `hash256`。创世块的区块头由 6 个字段拼成（第 8 章详细讲）：

```python
from bitcoin.hashes import hash256

header = (
    (1).to_bytes(4, "little")                # 版本
    + bytes(32)                              # 上一个区块的哈希：创世块没有上一个，全 0
    + bytes.fromhex("4a5e1e4baab89f3a32518a88c31bc87f618f76673e2cc77ab2127b7afdeda33b")[::-1]
    + (1231006505).to_bytes(4, "little")     # 时间：2009-01-03 18:15:05 UTC
    + (0x1D00FFFF).to_bytes(4, "little")     # 难度
    + (2083236893).to_bytes(4, "little"))    # 中本聪找到的那个 nonce

print(hash256(header)[::-1].hex())
# 000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f
```

这里用上了第 2 章的全部知识：整数用小端；默克尔根是按"显示顺序"给出的，所以要 `[::-1]` 颠倒成字节顺序；
算出的哈希要再颠倒一次才是人们熟悉的显示形式。

注意哈希开头那 10 个 `0`（40 个比特）。这不是巧合——最后那个字段 nonce 的值是 2083236893，
也就是说中本聪的电脑**至少试了二十亿次**才碰上这么一个哈希。这就是创世块的工作量证明。

## 本章小结

| 性质 | 含义 | 在比特币里的用途 |
|---|---|---|
| 确定性 | 同样输入永远同样输出 | 全网对同一笔交易算出同一个 ID |
| 雪崩效应 | 输入变一点，输出全变 | 防篡改 |
| 单向性 | 无法从输出反推输入，只能穷举 | 地址隐藏公钥；**工作量证明** |
| 抗碰撞 | 找不到两个输入产生同一输出 | 用 32 字节的哈希代表整笔交易/整个区块 |

* 比特币的两个组合：`hash256` = 两次 SHA-256；`hash160` = SHA-256 后接 RIPEMD-160。
* 工作量证明的核心是**不对称**：找答案要试很多次，验证只要一次。

## 思考题

1. 如果要求哈希以 6 个十六进制的 0 开头，平均要试多少次？以每秒 150 万次的速度大约要多久？
2. 有人说："哈希函数把无限多的输入映射到有限的输出，所以一定有碰撞，所以用哈希当 ID 不安全。"这个推理错在哪里？
3. 为什么说"雪崩效应"对工作量证明是必需的？（提示：如果输入加 1、输出也只是加 1，挖矿会变成什么样？）

<details><summary>参考答案</summary>

1. 16⁶ = 16,777,216 次；约 11 秒。（实验 8 里你会实测这个数。）
2. 碰撞"存在"不等于"找得到"。找到一对碰撞需要约 2¹²⁸ 次计算，这在物理上不可行。
   安全性从来不是"不可能"，而是"代价远远超出任何人的能力"。
3. 那样就可以直接算出需要的 nonce，而不必一个个试——工作量证明就不再证明任何工作量了。
   正因为输出对输入的依赖是"混沌"的，才没有任何捷径可走。
