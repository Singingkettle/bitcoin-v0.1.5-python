# 第 9 章　工作量证明与挖矿

> **本章目标**：弄明白"挖矿"到底在算什么、难度是怎么定的、为什么能稳定在 10 分钟一个块、
> 2100 万这个数是怎么来的。
>
> **对应源码**：[bitcoin/miner.py](../bitcoin/miner.py)、[bitcoin/params.py](../bitcoin/params.py)、
> `blockchain.py` 里的 `get_next_work_required`　　**实验**：[labs/lab08_mining.py](../labs/lab08_mining.py)

## 9.1　挖矿在算什么

第 3 章已经埋下了伏笔。现在可以把话说完整了：

> **一个区块要被全网接受，它的区块哈希（当成一个 256 位的整数）必须小于等于一个规定的数——"难度目标"（target）。**

```python
    def check_proof_of_work(self) -> bool:
        """工作量证明：区块哈希（当成一个 256 位整数）必须不大于难度目标。"""
        target = params.compact_to_target(self.n_bits)
        if target <= 0 or target > params.PROOF_OF_WORK_LIMIT:
            return False            # 声称的难度比允许的最低难度还低
        return self.get_hash() <= target
```

区块哈希是对 80 字节区块头做两次 SHA-256 的结果，它看起来是 0 到 2²⁵⁶ 之间的一个**均匀随机数**。
所以一次尝试成功的概率就是：

```text
p = target / 2²⁵⁶
```

矿工能做的只有一件事：**改动区块头，重算哈希，看看是不是够小；不够就再改、再算。**
区块头里专门留了一个 4 字节的字段让矿工随便改——`nNonce`（nonce 的意思是"只用一次的数"）：

```python
        prefix = block.header_bytes()[:76]          # 区块头前 76 字节不变
        while True:
            header = prefix + block.n_nonce.to_bytes(4, "little")
            if int.from_bytes(hash256(header), "little") <= target:
                return True                         # 挖到了！
            block.n_nonce = (block.n_nonce + 1) & 0xFFFFFFFF
```

这就是挖矿的全部核心代码。没有任何"聪明"的成分，纯粹是掷骰子——一个有 2²⁵⁶ 个面的骰子，
掷出的点数小于 target 就算赢。

> "哈希值以若干个 0 开头"是 "哈希值 ≤ target" 的通俗说法：target 越小，它的十六进制表示开头的 0 就越多，
> 小于它的哈希自然也以至少那么多个 0 开头。

## 9.2　难度目标的紧凑写法：nBits

target 是一个 256 位的数，但区块头里只给它留了 4 个字节（`nBits` 字段）。
办法是用一种类似**科学计数法**的压缩格式：

```text
nBits = 0x 1d 00ffff
           ││ └─────┴── 尾数（3 字节）
           └┴────────── 指数（1 字节）：target 一共占几个字节

target = 尾数 × 256^(指数 − 3)
```

就像 6.02×10²³ 用"有效数字 + 10 的几次方"表示一个大数，这里是"3 个字节的有效数字 + 256 的几次方"。

| | nBits | target（十六进制，64 位） | 每次哈希的成功率 |
|---|---|---|---|
| 主网创世难度 | `0x1d00ffff` | `00000000ffff0000…0000` | 约 1/43 亿 |
| 本私网创世难度 | `0x1f00ffff` | `0000ffff00000000…0000` | 约 1/65537 |

对应的函数在 `params.py`：

```python
def compact_to_target(bits: int) -> int:
    size = bits >> 24                   # 最高字节：指数
    word = bits & 0x007FFFFF            # 低 23 位：尾数
    if size <= 3:
        return word >> (8 * (3 - size))
    return word << (8 * (size - 3))     # 尾数左移 (指数-3) 个字节
```

（尾数为什么只有 23 位而不是 24 位？最高位被用作符号位了。这是原版借用 OpenSSL 大数格式带来的历史包袱，
`target_to_compact` 里有一段专门处理它的代码，源码注释里有解释。）

**私网为什么把难度调得这么低？** 主网创世难度下，纯 Python 每秒 150 万次哈希，
平均要 48 分钟才能挖出一个块，没法做实验。调低 65536 倍之后，约 0.04 秒一个块。
这是本项目对原版最主要的改动之一，`PROOF_OF_WORK_LIMIT`（允许的最低难度）也相应放宽了。

## 9.3　概率的视角

每次尝试成功的概率是 p，各次尝试互相独立。高中概率告诉我们：

* 平均需要尝试 **1/p** 次；
* 但具体哪次成功完全是随机的——可能第 1 次就中，也可能试了 5/p 次还没中。

实验 8 的第 3 步（真实输出）：

```text
   目标值（前几位）          理论平均次数        实测平均次数        每块平均耗时
   00fff...                          256             184         0.000 秒
   000fff...                       4,096           3,610         0.003 秒
   0000fff...                     65,536          49,104         0.036 秒
   00000fff...                 1,048,576         674,430         0.525 秒
```

实测值围绕理论值波动（样本越多越接近）。目标值多一个十六进制的 0，工作量就变成 16 倍。

**挖矿没有"进度"。** 已经试了 100 万次没中，不代表"快了"——下一次的成功率还是 p，和第一次一模一样。
这种性质叫**无记忆性**。它带来一个重要的公平性：

> 一个拥有全网 1% 算力的矿工，长期来看恰好能挖到 1% 的区块——不多也不少。
> 算力大的矿工没有任何"规模优势"，每一次哈希尝试都是一张独立的、等价的彩票。

## 9.4　不对称性：难找，易验

找到一个合格的 nonce 平均要试 1/p 次；而**验证**它只需要算 1 次哈希。
实验 8 第 4 步：

```text
   试了 3,476 次找到 nonce = 3475
   任何人验证：hash = 0000095f581ca1527af91df163f9d36dc7d8099a303a8c51f195ef4ed1bc6bed
              <= 目标值吗？True  （一次哈希，瞬间完成）
```

于是区块头里那个 nonce，就是一张**无法伪造的"工作收据"**：看到它，你就知道有人为这个区块付出了
大约 1/p 次哈希计算的代价（电费、机器折旧）——除此之外没有任何办法得到它。

回想第 1 章的女巫攻击：注册一百万个假身份是免费的，但一百万次哈希计算不是。
**工作量证明把"投票权"从可以无限伪造的"身份"，转移到了无法伪造的"物理世界里消耗掉的能量"上。**
这是整个比特币的安全基石。

## 9.5　4 字节的 nonce 不够用怎么办

nonce 只有 4 字节，最多 2³² ≈ 43 亿种取值。在主网今天的难度下，43 亿次全部试完也几乎不可能有一次成功。怎么办？

区块头里能改的不止 nonce：

* **时间戳 `nTime`**：每过一秒就可以换一个值；
* **coinbase 交易里的"额外随机数"（extra nonce）**：coinbase 的 `scriptSig` 是矿工可以随便写的。
  改动它 → coinbase 的哈希变了 → 默克尔根变了 → 区块头变了 → 又有 43 亿个新的 nonce 可以试。

原版的矿工循环里就有一个 `bnExtraNonce`，每组装一次新区块就加 1：

```python
            # coinbase：scriptSig << nBits << ++bnExtraNonce（后者是 CBigNum，按数据压栈）
            self.extra_nonce += 1
            script_sig = CScript().push_int(n_bits).push_bignum(self.extra_nonce)
```

还记得上一章主网第 9 号区块 coinbase 的 scriptSig 吗？`04 ffff001d  01 34`——
正是 `nBits`（0x1d00ffff）后面跟着一个额外随机数（0x34 = 52）。和我们的矿工写出来的格式一模一样。

## 9.6　组装候选区块

在开始"掷骰子"之前，矿工得先准备好一个候选区块（`Miner.create_new_block`）：

```text
1. 记下当前的链尖 prev，算出下一个区块应有的难度 nBits
2. 造一笔 coinbase 交易：输入为空，输出付给自己的公钥
3. 从内存池里挑交易装进区块（手续费规则见第 11 章），累计手续费
4. coinbase 的输出金额 = 区块补贴 + 这个区块里所有交易的手续费
5. 算默克尔根；时间戳 = max(前 11 个区块时间的中位数 + 1, 当前时间)
6. 开始从 nonce = 1 往上试
```

挖的过程中要时不时"抬头看一眼"（原版每试 262144 个 nonce 看一次）：

```python
            if block.n_nonce & NONCE_CHECK_MASK == 0:
                if block.n_nonce == 0:
                    return False            # 40 多亿个 nonce 全试完了
                if prev_hash is not None and self.chain.best_index.hash != prev_hash:
                    return False            # 别人先挖到了，链尖变了
                ...
```

**如果别人先挖出了这个高度的区块，你手上的候选区块就立刻作废**——它指向的 `hashPrevBlock` 已经不是链尖了。
必须基于新的链尖重新组装、重新开始。之前的计算全部白费。这就是为什么挖矿是一场"赢者通吃"的竞赛。

挖到之后（`found_block`）：

```python
        self.wallet.add_key(self.key)       # 先把收款密钥存进钱包（这样钱包才认得这笔 coinbase 是自己的）
        self.key = CKey.generate()          # 换一把新密钥
        ok = self.chain.process_block(block)   # 像处理别人发来的区块一样处理它
```

一个忠实于原版的细节：收款密钥**只在挖到块的那一刻**才存进钱包。
之前无数次没挖到的尝试，不会在钱包里留下任何痕迹。

## 9.7　难度调整：为什么总是 10 分钟

2009 年全网只有几台电脑，今天有数百万台专用矿机，算力增长了十几个数量级。
如果难度固定不变，现在一秒钟就能出几十亿个区块。

比特币的办法是**负反馈**：每隔 **2016 个区块**（按 10 分钟一个算，恰好两周），
所有节点各自回头看一下这 2016 个块实际花了多长时间，然后**按比例调整 target**：

```text
新 target = 旧 target × (实际用时 / 两周)
```

* 实际只用了一周（算力涨了，挖得太快）→ target 减半 → 难度翻倍；
* 实际用了四周（算力跌了）→ target 翻倍 → 难度减半。

```python
    def get_next_work_required(self, pindex_last):
        if (pindex_last.n_height + 1) % params.INTERVAL != 0:
            return pindex_last.n_bits           # 不到调整点：沿用上一个块的难度

        pindex_first = pindex_last
        for _ in range(params.INTERVAL - 1):    # 往回走 2015 步
            pindex_first = pindex_first.pprev

        actual_timespan = pindex_last.n_time - pindex_first.n_time
        actual_timespan = max(actual_timespan, params.TARGET_TIMESPAN // 4)     # 单次调整
        actual_timespan = min(actual_timespan, params.TARGET_TIMESPAN * 4)      # 最多 4 倍

        new_target = (params.compact_to_target(pindex_last.n_bits)
                      * actual_timespan // params.TARGET_TIMESPAN)
        new_target = min(new_target, params.PROOF_OF_WORK_LIMIT)
        return params.target_to_compact(new_target)
```

三个值得注意的地方：

1. **没有任何人"发布"难度。** 每个节点根据自己手里的区块链独立计算，因为大家的链相同、公式相同，
   算出的结果必然相同。一个区块如果声称了错误的难度，所有节点都会拒绝它。
2. **单次调整最多 4 倍**（上下限的钳制），防止时间戳被人操纵时难度剧烈跳变。
3. **一个保留至今的小失误**：代码往回走了 2015 步，量到的是 2015 个间隔的时间，却拿去和"2016 个间隔应该花的两周"比。
   所以即使出块节奏完美，难度也会每次上调 1/2016。实验 8 第 5 步能看到那个 0.9995。
   这个"差一错误"（off-by-one）修了就会导致分叉，所以真实的比特币至今保留着它。

### 为什么是 10 分钟

这是一个权衡：

* **太短**：一个区块传遍全球需要几秒到十几秒。如果出块间隔和传播时间在一个量级，
  经常会有两个矿工几乎同时挖出区块，造成大量分叉，白白浪费算力，也让攻击者更容易得手。
* **太长**：用户要等很久才能得到第一个确认。

10 分钟是中本聪凭经验选的一个保守值。

## 9.8　区块奖励与 2100 万

挖到区块的矿工可以在 coinbase 交易里给自己发钱，上限是：

```python
def block_value(n_best_height: int, fees: int) -> int:
    subsidy = 50 * COIN
    subsidy >>= n_best_height // 210_000        # 每 21 万个区块，右移一位 = 除以 2
    return subsidy + fees
```

`>>=` 是"按位右移"，二进制数右移一位就是除以 2（向下取整）。

* 第 0 ~ 209,999 个区块：每块 50 BTC
* 第 210,000 ~ 419,999 个区块：25 BTC
* 之后 12.5、6.25、3.125 ……

21 万个区块 × 10 分钟 ≈ 4 年。真实比特币的四次减半发生在 2012、2016、2020、2024 年。

**总量**是一个等比数列求和（高中数学）：

```text
210000 × (50 + 25 + 12.5 + 6.25 + …)  =  210000 × 50 × (1 + 1/2 + 1/4 + …)
                                       =  210000 × 50 × 2
                                       =  21,000,000
```

所以 **"2100 万"不是写在代码里的一个常数，而是"50 BTC 起步、每 21 万块减半"这条规则的数学后果。**

因为金额是整数聪，右移会向下取整，实际总量比 2100 万略少一点。`tests/test_util_params.py` 里精确地算了出来：

```python
def test_total_supply_is_just_under_21_million():
    total = sum(params.block_value(era * 210_000, 0) * 210_000 for era in range(34))
    assert total == 2_099_999_997_690_000          # 20,999,999.9769 BTC
```

右移 33 次之后补贴变成 0（大约在 2140 年）。此后矿工的收入只剩手续费。

> **忠实于原版的一个怪癖**：`block_value` 的参数是 `n_best_height`——"当前最佳链的高度"，
> 而不是"这个区块自己的高度"。原版的 `GetBlockValue` 用的就是全局变量 `nBestHeight`。
> 验证第 N 个区块时，最佳高度还是 N−1，所以严格按 0.1.5 的代码，第一个 25 BTC 的区块是第 210,001 个而不是第 210,000 个。
> 后来的版本改成了用区块自己的高度。

### coinbase 成熟期

挖矿所得不能马上花：必须等到它上面又盖了 100 个区块（`COINBASE_MATURITY = 100`）。

原因要到下一章才能讲透：链尖附近的区块有可能被"重组"掉。如果允许立刻花，一旦那个区块被重组掉，
这 50 BTC 就凭空消失了，所有从它派生出来的交易也连带作废，会波及无辜的人。等 100 个区块，就是等到它"几乎不可能再被推翻"。

钱包还要更保守一点，等 120 个（第 12 章）。

## 本章小结

* 挖矿 = 不断改 nonce、重算区块头的哈希，直到 **哈希 ≤ target**。纯概率，没有捷径，没有"进度"。
* `nBits` 是 target 的 4 字节压缩写法（3 字节尾数 + 1 字节指数）。
* 找到答案平均要 2²⁵⁶/target 次尝试，验证只要 1 次——nonce 是无法伪造的"工作收据"。
* **每 2016 个区块调整一次难度**，让出块间隔回到 10 分钟；每个节点独立计算，无需任何人发布。
* 区块补贴 50 BTC 起、每 21 万块减半，**等比数列求和得到 2100 万**。
* coinbase 要等 100 个确认才能花。

## 思考题

1. 某矿工的算力是全网的 5%。他平均多久能挖到一个块？他连续挖到两个块的概率是多少？
2. 如果有人把自己区块的时间戳故意写成一年以后，想骗过难度调整算法，会怎样？（提示：看 `check_block`）
3. 2140 年之后不再有新币，矿工靠什么活？如果手续费不够高会发生什么？

<details><summary>参考答案</summary>

1. 平均每 20 个块挖到 1 个，即约 200 分钟一个。连续两个都是他的：0.05² = 0.25%。
   一般地，连续挖到 k 个块的概率是 qᵏ，随 k 指数下降——下一章"等待确认"的安全性就来自这里。
2. `check_block` 规定区块时间戳不能比本机时间超前 2 小时以上，这样的区块直接被拒绝。
   另一头，`accept_block` 要求时间戳必须晚于前 11 个区块时间的中位数，所以也不能往回写太多。
   时间戳能被操纵的范围只有几个小时，相对于两周的调整周期影响有限。
3. 只靠手续费。如果手续费总额太低，挖矿无利可图，算力会退出，网络的安全性（攻击成本）随之下降。
   这被称为"安全预算"问题，是比特币长期经济学里一个仍在争论的开放问题。第 15 章会讨论。
</details>
